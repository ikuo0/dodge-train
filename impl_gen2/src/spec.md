# gen2 の目的

状況を単語ID列で表し、逆数重み付きONE-HOT総和を入力にしたNNで回避行動を選ぶ。直近300ms未満の外界情報を判断に使わず、250msの人間的な行動切り替えクロックで操作する。gen1は変更せず、gen2で独立して比較する。

# ゲームと操作

- 左は250msごとにランダム操作、右は250msごとにNNで操作する。
- 行動は左移動・右移動・待機の3種類。すべて250ms。移動速度180px/s、1回最大45px。壁では停止する。途中では判断し直さない。
- NNの応答待ちは左右のゲーム内時間を止める。応答後に倍速クロックの残り時間を消化する。
- 左右とも同じ発射・移動・衝突ルールを使用する。速度1/3/10/20/40倍、弾数、開始・停止・リセットを維持する。
- 正確な衝突判定はゲームの被弾数表示・描画のみに使う。衝突結果、正確な位置や弾配列はWorkerに送らない。

# 観測の遅延

- ゲーム内50msごとに位置と弾を単語化したスナップショットを保存する。
- 判断時点より300ms以上前のスナップショットだけを利用する。それより新しい弾の出現・移動・被弾は入力に反映しない。
- 開始直後は初期位置と「弾なし」を仮定する。履歴が足りない間も新しい情報を先取りしない。
- 自分が発行した移動命令は既知として、古い位置区画の中心から命令の時間積分で現在位置を推測する。現在の正確な自機座標を参照しない。推測位置も8区画に丸める。
- 50msの観測刻み・250msの判断刻みはゲーム内時間を使う。実時間の描画とは独立する。

# 状況単語

語彙は211種類。履歴長は最大64語。

- 行動3種類：`左移動250`、`右移動250`、`待機250`。
- 自機位置8種類：横45pxずつの `自機位置1`〜`自機位置8`。
- 弾144種類：到達区画8 × 到達時間6 × 横方向3。
  - 直線軌道を自機の高さy=513pxまで延長し、横45px単位の到達区画1〜8に丸める。画面外は端の区画へ丸める。
  - 到達時間は `[0,250)`、`[250,500)`、`[500,750)`、`[750,1000)`、`[1000,1500)`、`[1500,2000]` ms。代表値は125/375/625/875/1250/1750ms。
  - 横速度が−20px/s未満なら左向き、20px/s超なら右向き、その間は直進。
  - 例：`到達区画5_残り625ms_左向き`。
  - 到達が2秒より先、通過済み、被弾済みの弾は入力に含めない。
  - 最大12発。到達の近い弾を優先し、遠い弾から近い弾の順で並べる。
- `弾なし`、`観測遅延300ms`：各1種類。
- 判断用に相対到達54種類（相対区画−4〜＋4 × 到達時間6）を追加する。古い弾の到達区画と、自分の命令から推測した現在の区画との差を取り、±4に丸める。例：`相対到達-1_残り625ms`。左右の場所が違っても同じ回避関係を共有できるようにする。絶対到達144語は観測保存用で、NNへの弾入力は相対到達語に変換する。
- 入力順は「相対到達の単語群（なければ弾なし）、推測自機位置、観測遅延」。行動は3つの出力ヘッドで区別し、選択行動の単語は文章ビューワの末尾へ追加する。
- 各判断の新しい観測を使う。消えた弾を古い履歴から繰り返し入力しない。直前の状況単語列は文章ビューワに残す。

# 重み付きONE-HOTとモデル

- 直近から `1, 1/2, …, 1/64` を各IDのONE-HOTに掛けて総和する。同じIDは加算する。
- 入力211次元 → 隠れ48（tanh）→ 危険度3（行動別sigmoid）。隠れ層を共有し、学習対象の行動ヘッドと共有層を更新する。
- Vanilla JavaScriptのSGD。学習率0.01、交差エントロピー、隠れ勾配クリップ±1。外部MLライブラリ、RNN、Transformer、連続座標の追加入力は使わない。
- 次単語生成は行わない。NNは状況と候補行動から危険スコアを直接学習する。

# 教師データの設計

gen2は実被弾を報酬にした強化学習ではなく、遅延・量子化された文章から作る粗い危険予測をNNに学ばせる方式とする。避ける方向の学習を成立させるため、各観測で3行動すべての教師を作る。

- 教師関数もWorker側で単語ID列だけを受け取る。現在の正確なゲーム状態や将来の実弾道にはアクセスしない。
- 単語から到達区画の中心と到達時間の代表値を復元する。観測遅延300msを到達時間から差し引く。
- 候補の移動を最大500ms継続し、その後停止するという粗い計画を評価する。実操作は250msで見直すため、これは正確な未来シミュレーションではない。
- 自機半径9pxを18pxへ拡大し、弾半径4pxを加えた22pxを基準とする。さらに到達区画の半幅22.5pxと到達時間±125msの不確かさを加える。
- 到達時間が遅延補正後−125ms〜1.5秒の弾を対象に、候補位置との距離から0〜1のぼかした近接スコアを作る。時間の揺らぎに対する最大値、全弾の最大値を教師とする。
- 正確な円同士の当たり判定を教師にしない。安全の余裕を残すため、実際には当たらない近接も危険とする。
- この教師は粗い回避ヒューリスティックであり、実際の被弾確率ではない。発射位置だけでは失われていた到達先・到達時間を言語化することを重視する。

# 学習データとCPU予算

- 左右それぞれ8192件のリングバッファ。1件は「観測単語列、候補行動ID、危険教師値」。左右の履歴を連結しない。
- 初回START時に、相対区画−3〜＋3・到達時間6・自機位置8・行動3を組み合わせた1008件の粗い基礎教材で24000回更新する。実際の弾や正確な判定は使わない。更新回数表示にはこの基礎学習を含む。Workerで行うため、初回開始時は基礎学習の完了まで少し待つ。
- ゲーム内1秒ごとに左最新558件・右最新186件（3:1）と、基礎教材からランダムに256件を選んでシャッフルする。安全な場面ばかりの経験で危険時の回避を忘れないよう基礎教材を維持する。左右の不足側は存在する分だけ使い、他方で補わない。基礎教材は復習のため重複を許す。
- 前周期の未処理分は破棄する。学習待ちは最大1000件、処理済みはカーソルで進める。
- 1処理枠は最大8例・2ms、次の枠は実時間4ms後に予約する。1例の計算中は中断しないので2msは厳密なCPU上限ではない。キューが空なら学習しない。
- 更新回数、平均損失、学習待ち件数を表示する。平均損失は直前98%・今回2%の移動平均。
- 停止時は学習も停止、リセット時はモデル・データ・ゲームを初期化。速度・弾数設定は維持する。

# 行動選択と表示

- 推定はNNの出力だけで行い、教師関数を直接使って選ばない。
- 最小スコアとの差0.02以内は同等としてランダムに選ぶ。5%の判断では全候補から探索する。
- 壁方向も候補に残す。最新の壁到達を即時に判断へ漏らさない。実際のゲーム移動は壁で止まる。
- スコア0.5超を高リスクとして表示する。最後に高リスク候補があった判断をパネルに保持する。
- 文章ビューワには判断に使った遅延観測＋選択行動を最新10件保存し、実時間10秒ごとに表示する。

# 検証

`node --test impl_gen2/tests/prediction.test.cjs` で語彙、特徴、遅延の非漏洩、判断周期、学習の有界性、行動別学習とWorker連携を検証する。

`node impl_gen2/tests/simulation.cjs 180` で3つの固定乱数・各180秒のヘッドレス比較を行う。基礎学習24000例に加え、オンライン学習予算はゲーム内1秒128例に固定する。診断用 `--teacher` はNNを使わず教師で選択するため、製品の動作・NNの成績とは別扱いとする。ブラウザの実CPU時間や長期成績を保証する実験ではない。
