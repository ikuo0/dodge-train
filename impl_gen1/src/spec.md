# 基本方針

左右両画面のすべての状況単語を使い、次の単語の確率分布を同じNNで学習する。左はランダム行動、右はNNによる行動選択と経験収集を行う。学習バッチは左75%・右25%を基本とする。

被弾は衝突した瞬間に記録する。行動終了時の結果ラベルとして被弾・無被弾を付ける方式は使用しない。単独の無被弾は記録せず、弾イベント内の分類としてのみ使う。

# UI指示

- 縦にゲーム画面、コントロールパネルを並べる。
- ゲーム画面は縦長canvasを左右に並べる。
  - 左：ランダム行動・学習データ収集。
  - 右：NNによる行動選択・評価・学習データ収集。
- START / PAUSE、学習リセット、速度、弾数を操作できる。
- 速度は1倍→3倍→10倍→20倍→40倍→1倍と切り替える。
- ゲーム、データ収集、学習・推定はゲーム内時間基準で進める。描画は別のrequestAnimationFrameで行い、倍速時も描画回数を増やさない。
- 被弾数、1分・10分の被弾/分、行動、経過時間、左右合計の記録トークン数、NN更新回数、損失を表示する。
- 先読みリスクと未到達の有無を表示する。「判断状況」は危険な候補または未到達を検出した時に更新し、全候補が低リスクの間は直前の表示を保持する。
- 文章ビューワは右の行動選択時の末尾64トークンを最新10件保持し、実時間10秒ごとに表示を更新する。クリックで全文をコピーできる。

# ゲーム画面、ゲーム構成

- 上部に3つの発射口を置く。
  - 自機狙いと、画面最下部のどこかをランダムに狙う弾を発射する。
- 下部に自機を置き、左右に動く。
- 行動は6種類。
  - 左に画面幅の1/4または1/2移動。
  - 右に画面幅の1/4または1/2移動。
  - 300msまたは600ms待機。
- 左は行動完了後に次の行動をランダムに選ぶ。
- 右は行動が終わった瞬間に推定し、次の行動を決定する。
  - 初回は行動開始前に推定する。実行中の行動は完了まで継続し、途中で再推定・キャンセルしない。
  - 完了後に同じ行動を選んだ場合も新しい行動として開始する。
  - 一時停止からの再開時は実行途中の行動を継続する。
  - 壁で動けない方向は候補から除く。
- 推定応答待ちではゲーム内時間を止める。応答後に倍速クロックの残り時間を処理する。
- 被弾した弾は当たり判定を失い、その場でランダムに跳ね上がり、放り投げの軌道で画面外に消える。グラフィックはそのままで薄い色にする。

# イベントまとめ（状況説明単語）

語彙は合計64種類。下記のすべてを次トークン学習の正解にする。


- 弾の出現：48種類（発射位置8×速度3×予測被弾有無2）。
  - 画面下側1/3の領域に入る境界（上端から高さ2/3）を下向きに横切った瞬間に、弾ごとに1回だけ発生する。
  - 発射位置
    - 発射された瞬間の横座標を画面幅の8分割で1〜8に変換し、弾ごとに保持する。観測ライン通過時の横座標ではない。
  - 発生の瞬間に次の弾イベント定義を連結して弾イベント単語とする
  - 例: `1_SLOW_被弾`
  - 速度
    - `SLOW`, `NORMAL`, `FAST`
  - 観測時の自機位置を固定した場合に、弾の未来の直線軌道が自機に当たるかどうか
    - `被弾`, `無被弾`
    - 自機の当たり判定サイズを１とするなら、自機の当たり判定を前後左右に 0.5 ずつ広げて当たり判定を行う
- 自機の位置：8種類。
  - 横8分割の `自機位置{1-8}` を行動前に記録する。
  - 行動の完了時には位置を記録せず、次の行動開始時に現在位置と行動を連続して記録する。
- 自機の行動：6種類。
  - 開始時に `左0.25`、`左0.5`、`右0.25`、`右0.5`、`待機300`、`待機600` のいずれかを記録する。
  - 前述の通り `位置`, `行動` の順番はセットで登場するようにする
- 被弾：1種類。
  - 実際に弾が当たった瞬間に `被弾` を記録する。
  - 行動中・行動のない待ち時間のどちらでも記録し、複数回の衝突はそれぞれ記録する。
  - 行動終了時に被弾を再記録しない。
- 時間経過：1種類。
  - ゲーム内200msごとに `時間経過200` を記録する。
  - 時間チックで弾状況を複製しない。

記録例：`1_SLOW_被弾 → 自機位置6 → 待機300 → 時間経過200`。被弾は自機位置の後に固定配置せず、発生した時点に置く。

1. 推定時は実履歴に現在位置・候補行動を追加する。
2. 最大確率の単語を順に生成し、選ばれた単語が `時間経過200` の時にtickを1回数える。
3. tickが2回、または生成が20トークンに達したら終了する。
4. 全予測ステップの単独 `被弾` 尤度の最大値を候補のリスクとする。
5. 壁で動けない方向を除いた各行動候補を評価し、最小リスクの行動を選ぶ。


# 重み付きONE-HOT総和特徴

- 各予測対象単語の直前の最大64トークンを入力とし、対象単語自身は入力に含めない。
- 直近から順に `1, 1/2, 1/3, …, 1/64` の逆数重みを掛け、ONE-HOTを要素ごとに加算する。
- 同じ単語が複数回あれば、その重みを加算する。65個以上前は使わない。
- 推定・先読みでも、次に予測する単語を基準に同じ加工を行う。
- 時系列の厳密な順序は保持しない。重みの差による大まかな時間情報を使う。
- 特徴ベクトルは64次元。NNは64→128→128→64、隠れ層はtanh、出力は全語彙softmax。
- TransformerやRNN、外部MLライブラリは使わず、Vanilla JavaScriptで実装する。

# 学習構成・トリガー

- 学習データ収集は左右両画面の全トークン到着時に行う。
  - 各単語Yと、その直前の最大64単語Xを1件として保存する（stride=1）。
  - 行動・自機位置・弾・時間経過・被弾のすべてが正解になる。
  - 最初の単語は空の履歴を入力とする。
  - 過去の被弾も通常の履歴として残す。
  - 左右のトークンは送信元を付けてWorkerへ送る。履歴は左右別に保持し、他方の単語が学習入力へ混ざらないようにする。
- 学習データは左右それぞれ全語彙共通の8192件リングバッファに保存し、各々古い例から上書きする。
- 被弾・無被弾の個別バッファ、件数合わせ、間引きは廃止する。実際の単語の出現頻度を保つ。
- モデル更新はゲーム内1000msごとに、左の最新750件・右の最新250件、合計最大1000件を使って行う。
  - 片側の割当件数が不足する場合は他方の未選択の最新例で補い、合計最大1000件とする。両側合わせても不足する場合は存在する件数だけ使う。両側0件なら更新しない。
  - 1バッチ内で同じ例を重複選択しない。左右の選択例を混ぜてシャッフルし、先頭から順に学習する。
  - 過去の例を繰り返し学習してよい。被弾例がなくても他の単語を学習する。
  - 更新は最大8ms・16例ずつに分割する。同じ1000ms周期内では未処理分を次の処理枠へ持ち越すが、次の周期では未処理分を削除して新しいバッチに置き換える。学習待ちは最大1000件で、元のリングバッファは削除しない。
- データ、履歴、重みはメモリ内のみ。学習リセットで全て初期化する。


被弾の損失重みは1・5・10・15・20倍の5段階で選択でき、初期値は1倍。単独の `被弾` が正解の例だけ、交差エントロピー `L = -w × log P(被弾)` とその勾配に重みを適用する。他の正解（弾イベント内の被弾を含む）は重み1。既存の隠れ層勾配クリップは維持する。変更は次の学習例から適用し、学習リセット・一時停止でも選択を維持する。再読み込み時は1倍へ戻る。表示の平均損失は設定間で比較できるよう重み適用前の交差エントロピーの移動平均（直前98%・今回2%）を使う。推定は重み付き学習後のモデルの尤度を使用する。

# 推定・短期先読み

- 右の実履歴に推定時の現在位置を1個追加し、その後に評価対象の行動を1個追加して、各候補を独立に評価する。壁で動けない方向は除外する。
- 全語彙softmaxから最大確率の単語を選び、予測履歴へ追加する。同率の場合はトークンIDが小さい単語を選ぶ。
- 最大確率の生成単語が `時間経過200` の時にtickを1回数える。同率時はトークンIDが小さい単語を選ぶため、時間単語が同率でも選ばれなければ数えない。
- tickが2回、または生成が20トークンに達したら終了する。行動・単独の被弾・弾イベントは終了条件にしない。
- リスクは全予測ステップにおける単独被弾確率の最大値：`risk(a) = max_t softmax(logits_t)[被弾]`。
  - 候補行動を追加した直後の予測から、2回目のtickまたは20個目の単語を選ぶ予測までを含める。
  - 20トークンでtickが2回に届かなくても、その時点までの最大値を使う。リスク1への置換や未到達扱いはしない。
  - 確率の累積や2語正規化は行わない。一定時間内の被弾確率ではなく、生成経路上の被弾尤度のピークである。
- 最小リスクの行動を選ぶ。同点（差1e-12以内）の候補だけランダムに選ぶ。
- スコアが0.5より高ければ「被弾リスク高」、それ以下なら「被弾リスク低」。
- 生成トークンは実履歴・学習データへ追加しない。倍速でも生成上限は変えない。

# 弾イベントの判定詳細

- 弾ごとに、画面下側1/3の領域に入る境界、すなわち上端から高さ2/3（画面高さ560pxではy=560×2/3px）の観測ラインを下向きに横切った時に1回だけ記録する。
- 発射位置は発射された瞬間の横座標を使用する。画面幅360pxを45pxずつ8分割し、左から1〜8とする。区分は `floor(発射時の横座標 / 360 × 8) + 1` を1〜8に丸める。弾が移動しても発射位置は変わらない。
- 弾イベントは `{発射位置1〜8}_{SLOW|NORMAL|FAST}_{被弾|無被弾}`。8×3×2＝48種類。自機から見た方向・観測位置・底部着弾位置は単語に含めない。
- 予測被弾は観測時の自機位置を固定して判定する。記録後に自機が移動しても、同じ弾の発射位置・被弾分類を再記録しない。
- 自機は半径9pxの円。予測被弾では直径を基準に各方向へ0.5倍拡張し、半径18pxとする。弾半径4pxを加え、弾の未来の直線軌道との最短距離が22px以下なら被弾分類とする。実衝突判定は従来のまま。
- 速度は135px/s未満がSLOW、165px/s未満がNORMAL、それ以上がFAST。
- 同一シミュレーション刻みでは弾配列順に観測・実被弾を記録し、その後に行動完了を処理し、時間チックを記録する。次の行動開始時には現在位置・行動を連続して記録する。
