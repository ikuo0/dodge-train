# Dodge Train / gen1

`src/index.html` を静的HTTPサーバー経由で開いてください。Web Workerを使うため、`file://` で直接開く方法には対応しません。ビルドや外部ライブラリは不要です。

`./impl_gen1/copy_to_contents.sh`（リポジトリルートから実行）で、公開に必要なファイルを `docs/gen1/` にコピーできます。同名ファイルは上書きします。GitHub Pagesの公開元は `main` ブランチの `/docs` を選択してください。

- `src/spec.md`：仕様書
- `src/index.html`：2画面と操作パネル
- `src/style.css`：レイアウト
- `src/game.js`：ゲーム、描画、イベント記録、200msごとの時間経過・行動完了時の推定
- `src/learn.js`：Web Worker、重み付きONE-HOT、全結合NN、学習データの収集・1000msごとの学習

左画面はランダムに行動し、右画面は行動が終わった瞬間にNNで推定して次の行動を決定します。移動は画面幅の1/4・1/2、待機は300・600msです。初回は行動開始前に推定し、実行中の行動は完了まで継続します。完了後に同じ行動が選ばれた場合も新しい行動を開始します。一時停止からの再開時は実行途中の行動を継続します。

行動開始時に現在の自機位置、その行動の順で連続して記録します。完了時には位置を記録しません。`被弾` は衝突した瞬間に記録し、終了時の被弾・無被弾ラベルは付けません。待機中の衝突も記録します。学習には左のランダム行動と右のNNによる行動の両方の経験を使います。バッチは左75%・右25%を基本とします。履歴は左右別々に保持し、右の履歴は推定入力と文章ビューワに使います。推定の応答待ちではゲーム内時間を止めます。

語彙は64種類です。行動6、自機位置8、弾48（発射位置8×速度3×予測被弾有無2）、実被弾1、時間経過1を記録します。弾は画面下側1/3の領域に入る境界（上端から高さ2/3）を下向きに横切った時に一度だけ分類します。単語は `1_SLOW_被弾` のように、発射時の横座標を画面幅の8分割で表す1〜8、速度、予測被弾有無を連結します。発射位置は弾ごとに保持し、観測時の横座標や自機位置では変わりません。予測被弾は観測時の自機位置を固定した未来の直線軌道で判定します。弾イベントの予測被弾と、実際の衝突を記録する単独の `被弾` は別の単語です。判定の詳細は `src/spec.md` を参照してください。

左右すべての記録単語を次トークン学習の正解Yにします。入力XはYの直前の最大64トークンで、Y自身を含めません。最初の単語は空の履歴から学習します。行動・位置・弾・時間経過・被弾の全てを対象にし、実際の出現頻度を保ちます。被弾と無被弾の件数合わせ・間引きは廃止しました。学習トークン数は左右合計です。左右の履歴をつないで教師入力を作ることはありません。

左右それぞれ全語彙共通の8192件リングバッファに入力と正解を保持します。ゲーム内1000msごとに左の最新750件と右の最新250件、合計最大1000件を学習し、被弾データがなくても更新します。片側の割当が足りなければ他方の未選択の最新例で補い、合計でも足りなければ存在する件数だけ使います。バッチ内の重複はなく、左右の例を混ぜてシャッフルし、先頭から順に学習します。同じ例を繰り返し学習して構いません。Workerは最大8ms・16例ずつに処理を分割します。ゲーム内1000msごとに前周期の未処理分を削除し、最新の例から作った新しいバッチへ置き換えます。学習待ちは最大1000件で、元のリングバッファは保持します。

重み付きONE-HOT総和は、直近から順に `1, 1/2, 1/3, …, 1/64` の逆数重みを掛けて加算します。推定・先読みも同じ加工を使います。NNは入力64次元、隠れ層128次元×2層（tanh）、出力64クラスのsoftmaxです。

推定は現在位置、その候補行動の順で履歴に追加し、最大確率の単語を順に生成します。選ばれた単語が `時間経過200` の時にtickを数え、2回または20トークンで終了します。行動や被弾では終了しません。最初と終了時を含む全予測ステップの単独被弾尤度の最大値をリスクとします。20トークンでtickが2回に届かなくてもリスク1には置き換えません。最小リスクを選び、同点のみ抽選します。生成内容は実履歴・学習データに混ぜません。

STARTで開始、PAUSEでゲームと学習を停止します。学習リセットはモデル、履歴、ゲーム、統計を初期化して再開します。タブが非表示でもWorkerのクロックで継続し、描画は表示中のみ進みます。ブラウザの省電力制御やタブの凍結、PCのスリープで進行が遅れたり停止したりする場合があります。停止期間をまとめて高速再生することはありません。履歴・重みはメモリ内のみで、再読み込み時に消えます。

「速度」は1倍→3倍→10倍→20倍→40倍→1倍と切り替えます。ゲーム進行・データ収集・推定・学習周期はゲーム内時間で統一し、経過時間と被弾/分もゲーム内時間で計算します。速度設定は一時停止・学習リセット後も維持します。描画は別のrequestAnimationFrameで行い、倍速設定によって描画回数は増やしません。推定応答後に残りのゲーム内時間を進め、進んだ時間を学習周期にも反映します。実際の速度はCPU性能とブラウザの制御に依存します。

「弾数」は従来量の約1/4を標準とし、その倍・半分を選べます。左右の発射間隔を2・4・8倍にして調整し、変更時は次の発射までの残り時間も調整します。画面内の弾と弾速は変わりません。学習リセット後も設定を維持します。

「判断状況」はいずれかの候補が高リスクまたは先読み未到達となった時だけ更新します。判断時刻・自機位置、6行動のスコア・判定結果・選択行動を表示します。全候補が低リスクの間と一時停止中は直前の表示を保持し、学習リセットで消去します。

文章ビューワは右画面の推定応答時の履歴を最新順に最大10件表示します。各行は末尾64トークンを単語に変換し、実時間10秒ごとに更新します。クリックで全文をコピーします。コピーにはHTTPSまたはlocalhostとクリップボードへのアクセスが必要です。学習リセットで履歴も消去します。

被弾/分はゲーム内10秒を1区間とする60区間のリングバッファで集計します。「1分」は直近6区間、「10分」は直近60区間の被弾数を毎分換算し、10秒ごとに更新します。区間不足時は完了済み区間だけで換算し、最初の10秒間は現在までの時間で暫定表示します。集計中の未完了区間は、最初の区間を除いて次回まで含めません。累積被弾数は別に表示します。

検証：`node --test impl_gen1/tests/prediction.test.cjs`

被弾の損失重みは1・5・10・15・20倍の5段階で選択でき、初期値は1倍。単独の `被弾` が正解の例だけ、交差エントロピー `L = -w × log P(被弾)` とその勾配に重みを適用する。他の正解（弾イベント内の被弾を含む）は重み1。既存の隠れ層勾配クリップは維持する。変更は次の学習例から適用し、学習リセット・一時停止でも選択を維持する。再読み込み時は1倍へ戻る。表示の平均損失は設定間で比較できるよう重み適用前の交差エントロピーの移動平均（直前98%・今回2%）を使う。推定は重み付き学習後のモデルの尤度を使用する。
