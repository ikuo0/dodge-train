# Dodge Train / gen1

`src/index.html` を静的HTTPサーバー経由で開いてください。Web Workerを使うため、`file://` で直接開く方法には対応しません。ビルドや外部ライブラリは不要です。

`./impl_gen1/copy_to_contents.sh`（リポジトリルートから実行）で、公開に必要なファイルを `docs/gen1/` にコピーできます。同名ファイルは上書きします。GitHub Pagesの公開元は `main` ブランチの `/docs` を選択してください。

「判断状況」の下の文章ビューワは、右画面の行動選択時の履歴を最新順に最大10件表示します。各行は履歴の末尾64トークンを単語に変換してカンマで区切り、実時間10秒ごとに更新します。行をクリックすると、表示しきれない部分を含む全文をコピーします。コピーにはHTTPSまたはlocalhostとクリップボードへのアクセスが必要です。学習リセットで履歴も消去します。

- `src/index.html`：2画面と操作パネル
- `src/style.css`：レイアウト
- `src/game.js`：ゲーム、描画、イベント記録・200msチック、1500msの行動固定・結果判定
- `src/learn.js`：Web Worker、語彙、全結合NN、オンライン学習、候補探索

左のランダム行動と右のNNが選んだ行動の両方を、同じNNの学習に使います。左右の履歴はゲーム側で別々に保持し、結果ごとにその側の行動開始時の最大128トークンを添えて送ります。Workerの保存用リングバッファは合計8192トークンを共有しますが、学習・再学習は保存した開始時点の入力だけを使い、左右の生トークン列をつないで入力を作ることはありません。無被弾の1/5抽出は左右それぞれで行い、被弾は両側とも全件採用します。画面の学習トークン数・更新回数・損失は左右合計です。

STARTで開始、PAUSEで停止します。学習リセットはモデル、履歴、ゲーム、統計を初期化して再開します。タブが非表示でもWorkerのクロックでゲームと学習を継続します。描画は表示中のみ進みます。ブラウザの省電力制御によって進行が遅くなったり、タブの凍結やPCのスリープで停止する場合があります。停止期間をまとめて高速再生することはありません。

語彙は行動7種類、自機位置8区分、弾の危険度2×方向3×速度3、被弾、無被弾、弾なし、200ms経過、移動完了、弾退出、被弾発生、待機完了の計41種類。重み付きONE-HOT総和は、直近から32トークンを1〜0.1の線形重み、33番目以降を0.1から1トークンごとに0.97倍する重みで加算します。直近を1番目とすると、重みは `n <= 32: 1 - 0.9 × (n - 1) / 31`、`n >= 33: 0.1 × 0.97^(n - 32)` です（32番目0.1、33番目0.097）。直近128トークンを入力し、隠れ層64次元×2層（両層tanh）、41クラスsoftmaxで結果を学習します。

150msごとの状況の定期記録は廃止しました。弾が上端から1/3の観測ラインを越えた時、弾の危険度・相対方向が変わった時、観測中の弾が退出した時、自機の位置区分が変わった時、移動・待機が完了した時、実際に被弾した時にトークンを追加します。観測中の弾がなくなった時は弾なしを記録します。ゲーム内時間200msごとに専用の「200ms経過」トークンだけを追加し、時間チックで弾状況を複製しません。

行動選択時は、履歴に現在の弾状況と自機位置を加え、最後に移動候補を置きます。その行動を1500ms固定し、指定の移動・待機が完了しても次の判断まではその位置で待ちます。区間内で1回でも被弾したら被弾、それ以外は無被弾を1トークン付けます。実際の被弾発生イベントは文脈専用で、学習の正解になる被弾トークンとは区別します。教師入力には区間開始時の最大128トークンを保存して使い、途中のイベントや時間チックがその区間の入力へ混ざらないようにします。左右とも1500msごとの境界で次の行動を選び直します。推定の応答待ちではゲーム内時間を止め、推定時と実行開始時の状態を一致させます。

推定時も完了済みの履歴に `[現在の弾状況] → [移動候補]` を追加して、次トークンの被弾・無被弾の確率を比較します。無被弾の確率が被弾以上の候補を優先し、その中で被弾確率が最も低い行動を選びます。全候補が被弾予測なら最もリスクが低い候補を選び、最小スコアとの差が1ポイント以内の候補は同等としてランダムに選びます。無被弾予測の候補があれば、その範囲内で選びます。端に向かう移動は端では除外します。予測結果と、無被弾の1/5サンプリングを補正した被弾スコアを表示します。これは次の1500ms区間のモデル推定であり、行動完了までの安全を保証するものではありません。先読み探索と手数選択は使用しません。左右の弾は別々に生成されるため、短時間の被弾数にはばらつきがあります。

「速度」ボタンで1倍→3倍→10倍→1倍と切り替えます。左右のゲーム進行・データ収集・推定周期をまとめて速め、Workerの学習処理枠と再学習量も増やします。200msの時間チック・1500msの結果判定と行動選択はゲーム内時間基準です。経過時間と被弾/分もゲーム内時間で計算します。速度設定は一時停止・学習リセット後も維持します。実際の速度はCPU性能とブラウザの制御に依存します。

「弾数」は従来量の約1/4を基準（初期値）とし、基準の2倍（従来量の約1/2）と半分（従来量の約1/8）を選べます。左右とも発射間隔を2・4・8倍にして発射量を調整します。変更時は次の発射までの残り時間も調整し、画面内にある弾はそのまま進みます。弾速は変えません。学習リセット後も選択した弾数を維持します。

学習例は被弾・無被弾の位置で作ります。正解Yはその結果トークン、入力Xはその行動を選んだ時点の最大128トークン（弾状況・移動候補まで）です。結果が確定するまでに記録した観測は、この正解の入力には混ぜません。保存した開始時点の入力は再学習でも使います。正解自身は入力に含めませんが、入力内の過去の被弾・無被弾はそのまま含めます。位置・弾状況・行動・各種イベント・時間チックは入力専用で、正解としての学習や再学習には使いません。

無被弾を正解にする学習は5件に1件だけ採用し、被弾は間引きません。文脈が途切れないよう、8192トークンの記録用リングバッファには無被弾も含めた全文脈を残し、学習対象かどうかを別のフラグで管理します。再学習にも同じフラグを適用するため、間引いた無被弾が再学習で復活することはありません。間引いた無被弾の更新分は保存範囲内の過去の結果トークンを正解とする学習で補います。未処理の再学習は次の処理枠へ持ち越し、最大8192件分に制限します。被弾もリングバッファの保存範囲を過ぎれば上書きされますが、学習済みの重みは残ります。推定時は `P(被弾) / (P(被弾) + 5 × P(無被弾))` でサンプリングによる偏りを補正します。再学習やモデル誤差があるため、補正後も実測の発生率を保証するものではなく、行動比較用のスコアです。

Workerの学習は1スライス最大4ms・48例（3倍時12ms・144例、10倍時16ms・480例）、追加データの学習に少量の再学習を加えます。記録用リングバッファは8192トークン。表示フレームと学習を分離し、停止中は学習もしません。履歴・重みは保存しません。

検証：Node.jsのある環境で `node --test impl_gen1/tests/prediction.test.cjs` を実行します。

「判断状況」枠は、行動候補のどれかで被弾の確率が無被弾を上回った時だけ更新します。判断時のゲーム内時刻・自機位置、7行動の被弾スコア・結果予測・選択行動を表示し、端で動けない候補は候補外と表示します。危険な候補を避けて無被弾予測の行動を選んだ場合も更新します。全候補が無被弾予測の間と一時停止中は直前の表示を保持し、学習リセットで消去します。

弾の相対方向は現在のX座標で分類します。描画上の自機幅20pxを基準に、自機中心から左右30px以内（自機3個分の全幅60px、境界を含む）を正面、それより左・右をそれぞれ左・右とします。危険度の判定範囲と衝突判定は従来どおりです。

被弾/分はゲーム内10秒を1区間として、60区間のリングバッファで集計します。「1分」は直近6区間、「10分」は直近60区間の被弾数を毎分換算し、10秒ごとに更新します。区間が足りない間は完了済み区間だけで換算し、最初の10秒間は現在までの経過時間で暫定表示します。集計中の未完了区間は、最初の区間を除いて次回更新まで含めません。累積被弾数は引き続き別に表示します。一時停止中は集計も止まり、学習リセットで初期化します。
